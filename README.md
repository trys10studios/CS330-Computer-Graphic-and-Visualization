# CS330-Computer-Graphic-and-Visualization
CS330 Computer Graphic and Visualization using OpenGL

My approach to designing software includes pseudocode, design documentation, and kanban cards to keep track of what changes have been made, keeping track of bugs and their solutions, and having a deadline for each kanban card to keep track of how much time has been spent on each solution. 

The sheer size of creating complex objects from primitive object types forces me to have to make sure folders are correctly named, comments are easy to read and understand, and code is as modular as possible. I do my best to make functions that do one thing and only one thing, and allow for reuse, rather than copying and pasting the same lines of code elsewhere in the source code. 

My design approach, as I am a digital and traditional artist as well, is to use a construction method. The idea is to use the simplest form you can to capture the object, character, or subject in your scene as quickly and efficiently as possible. For instance, using spheres, cubes, etc., to compose a figure of a person is usually enough to create or capture the essence of the person or character using poses. 

Reusing and using the DRY (Do not Repeat Yourself) principle reminds me of, “if I need it once, I probably will need it again.” This principle reinforces code modularity, which makes scaling easier in the future as well as making it easier to read, effectively future proofing the code. Keeping the design simple makes changes easier as well. An example would be, using a box for the body of a character, rather than fully designing the torso from complex shapes, as if the model needs to be scaled or changed in some ways, it is much harder to do when manipulating lots of vertices, rather than a simple set from basic shapes. Once the scene is set up the way the client wants or intended, then further details can be added. This saves tons of development and design time. 

My approach to developing programs, games, and applications is the same as my design approach. Start with a simple prototype, get a working idea setup, make sure the basic ideas of the client are met, and keep iterating until they are happy. Trying to use the waterfall approach, writing code without ever looking back or asking the client, and hoping all is well in the end is antiquated and does not serve either party. Games are somewhat a caveat to the agile method though, and since your end-user is a player, unless you use alpha testing, it is difficult to use the agile method in its entirety. However, iterative development is often the best approach with games, creating as much as you can in the prototype stage to not have to change tons of code in a massive code base. The idea is to create, test, and modularize as much as possible so the finished game is a scaled version of the prototype. Leaving the last bit of work to music and art. 

While working on my 3D scene I added an extensive number of comments for myself and sectioned off as much as I could so the code would be more manageable. Using simple objects to make more complex ones leads to a lot of reuses of the same type of object, and so compartmentalizing becomes paramount and using comments to separate helps to make it more accessible, noting things like what type of object it is. In my scene, the “Cheeseburger” and all its components were separated out with comments using headers so when I am scrubbing through the code, I can find it faster. Also, the use of CTRL-F is an incredibly useful shortcut. 

I paid careful attention to commenting as this helped me to keep things organized. I made sure to write functions to modularize the code for reuse and used good naming conventions to make the code easier to follow and to allow for simpler commenting and efficacy. 

I have read many times that video games are the most complete use of computer science knowledge, and with my experience in game development, I agree. Modularizing code for scalability, commenting, keeping security in mind from the beginning, and many more principles I have learned through my computer science education, apply directly to video game, web, mobile, and application development. 

I have an extensive amount of experience with 3D modeling and animation, and 2D drawing and animation. This course forced me to look at 3D graphics from a rudiemntary or more nuanced perspective. The “closer to the metal” approach has a lot to offer for computer science students and I recommend anyone interested in learning about 3D visuals to take a deep dive into 3D graphics using OpenGL. Having experienced a low-level approach to computer graphics in 3D and 2D using OpenGL, I have much more appreciation for tools such as Blender, Maya, and 3DS Max such as being able to change diffuse, ambient, or specular shaders in real time.
